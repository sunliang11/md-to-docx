# WMS 监控工作站使用手册

> 面向客服顾问 | 版本 v1.1 | 更新日期：2026-08

---

## 一、快速入门

### 1.1 从哪里进入

WMS PC 端 → **基础设置** → **监控工作站**

进入后左侧为导航菜单，右侧为查询与详情区域。顶部面包屑可逐级回退（如：接口分析 → 某接口 → 某次请求）。

### 1.2 工作站能做什么

| 能力 | 说明 |
|------|------|
| 查单次请求 | 按时间、TraceID、操作人等条件检索，看完整执行过程（瀑布图） |
| 按接口/SQL 聚合排行 | 找出「谁最慢、谁最容易出错」 |
| 看正在跑的请求 | 实时观察当前卡在哪一步 |
| 采 JVM 线程快照 | 怀疑锁竞争、死锁、全面超时时使用 |
| 查大对象 | 数据库或云盒（外部接口）返回数据过大 |

### 1.3 三类数据源（必记）

客服排查时首先要分清数据从哪来，否则容易在错误菜单里浪费时间。

| 类型 | 采集方式 | 对应菜单 |
|------|----------|----------|
| **应用侧** | WMS 内嵌监控 Agent，记录每次 API 请求及其中的 SQL、云盒调用 | 入站请求、接口分析、SQL 排行、实时运行 |
| **数据库侧** | MariaDB 慢查询日志，经 Vector 采集写入 ES | 慢查询、大对象监控（数据库 Tab） |
| **实时快照** | WMS 进程内存，不落库，刷新或重采即变 | 实时运行、线程诊断 |

**易混点：SQL 排行 vs 慢查询**

- **SQL 排行**：应用执行过的 SQL，能关联到具体接口、操作人、TraceID。
- **慢查询**：数据库慢日志，可能包含定时任务、直连 SQL，不一定对应某次 WMS 操作。

## 二、前置条件与「查不到数据」怎么办

### 2.1 环境必须满足的条件

| 条件 | 说明 | 影响范围 |
|------|------|----------|
| `monitor.enabled=true` | WMS Plus 已接入监控 Agent 并开启 | 全部应用侧功能 |
| `monitor.es.url` 已配置 | Agent 写入 + 工作站查询同一 ES 集群 | 入站请求、接口分析、SQL 排行、慢查询、大对象 |
| `monitor.wms.url` 已配置 | 工作站代理到 WMS 的实时接口 | 实时运行、线程诊断 |
| 请求带 TraceID | 无 TraceID 的请求不会被采集 | 入站请求及相关下钻 |
| MariaDB 慢日志 + Vector | 慢日志开启且推送到 `/api/slowlog` | 慢查询、大对象（数据库 Tab） |

WMS 升级或 Agent 更新后需**重启 WMS**，否则实时运行、线程诊断可能不可用。

### 2.2 时效与数据保留

| 能力 | 延迟 / 保留 | 客服话术 |
|------|-------------|----------|
| 历史请求 / SQL / 云盒 | 请求结束后约 200ms 写入；默认保留 **7 天** | 「超过一周的历史查不到是正常的」 |
| 慢查询 | **分钟级**延迟（DB 刷盘 + Vector 传输） | 「刚发生的慢查可能还没同步过来，稍等几分钟再查」 |
| 实时运行 | 约 **1 秒**刷新；仅反映**当前连上的那台 WMS 实例** | 「多节点环境要确认连的是哪台服务器」 |
| 线程诊断 | 点击时**一次性快照**，非持续监控 | 「这是某一瞬间的照片，不能当监控大盘轮询」 |

### 2.3 常见「空白页」转单指引

| 现象 | 可能原因 | 转给谁 / 查什么 |
|------|----------|-----------------|
| 所有菜单都没数据 | `monitor.enabled=false`、ES 不通、Agent 未随 WMS 重启 | 运维：检查 Agent 配置与 ES 连通 |
| 仅慢查询 / 大对象 DB 无数据 | MariaDB 慢日志未开或 Vector 未推送 | 运维：检查慢日志与 Vector 链路 |
| 仅实时运行 / 线程诊断报错 | `monitor.wms.url` 错误或 WMS 不可达 | 运维：检查 WMS 服务与代理地址 |
| 偶发历史数据缺失 | ES 故障期间数据写入本地 deadletter，恢复后补写 | 研发：确认 ES 恢复时间与补写状态 |
| 列表翻页报「超出范围」 | 时间范围太大，命中 ES 1 万条上限 | 缩小结束时间范围后重查 |

### 2.4 关键阈值

| 指标 | 默认值 | 含义 |
|------|--------|------|
| 应用侧慢 SQL | ≥ 1000ms | 入站请求「慢 SQL」列、实时运行「慢 SQL 请求」 |
| 实时「卡住」— 等 DB/外部 | ≥ 5 秒 | 进行中请求的「卡在数据库 / 卡在外部接口」 |
| 实时「卡住」— 无 I/O | ≥ 60 秒 | 「无 I/O 活动」阶段 |
| 大对象（数据库） | ≥ 1MB 或 ≥ 1000 行 | 纳入大对象监控 |
| 大对象（云盒） | 响应 ≥ 1MB | 纳入大对象监控 |
| 线程 CPU 偏高 | ≥ 40%（100ms 采样窗口） | 线程诊断 KPI「CPU 偏高」 |

## 三、场景排查指南

每个场景按：**客户怎么说 → 先去哪 → 重点看什么 → 下钻 → 何时转研发**。

---

### 场景 1：操作报错，客户能提供 TraceID 或大致时间

**客户怎么说**：「点保存报错了」「刚才 10:30 左右出库失败」

| 步骤 | 操作 |
|------|------|
| 先去哪 | **入站请求** |
| 怎么筛 | 结束时间调到事发时段；有 TraceID 直接填；否则筛「是否异常 = 是」 |
| 重点看什么 | 错误信息列；URL 旁「**客**」徽章（客制代码 `wms-custom` 相关） |
| 下钻 | 点击行 → **请求详情** → 看「瓶颈诊断」、错误 Tab、瀑布图 |
| 转研发 | 客制问题（有「客」徽章）优先转客制团队；标准产品带 TraceID + 错误截图 |

**请求量趋势图**：蓝柱 = 正常次数，红柱 = 异常次数。红柱突然变高说明该时段报错增多；点击柱子可缩小时间范围继续细查。

---

### 场景 2：某个菜单/功能变慢（事后排查）

**客户怎么说**：「入库单保存越来越慢」「盘点提交要等很久」

| 步骤 | 操作 |
|------|------|
| 先去哪 | **接口分析** |
| 怎么筛 | 结束时间覆盖慢的时间段；可按菜单名、操作描述缩小范围 |
| 重点看什么 | 默认按 **P95** 降序；同时关注**错误率**偏高的接口 |
| 下钻 | 点击接口行 → **接口详情** → 看「耗时分布」+「SQL 模式聚合」 |
| 转研发 | P95 持续偏高且 SQL 模式中有单条极慢或执行次数异常多时，带接口 URL + 截图转研发 |

**接口详情内进一步判断**：

1. **耗时分布**红色柱子高 → 点柱子列出慢请求 → 进请求详情看瀑布图。
2. **SQL 模式聚合**某类 SQL 执行次数多 → 可能重复查询；某类平均耗时高 → 可能单条 SQL 慢。
3. 打开「**对比**」开关，与昨天同期比，确认是偶发还是持续变差。

---

### 场景 3：怀疑某条 SQL 拖慢业务（应用侧）

**客户怎么说**：「是不是查库存的 SQL 有问题」「这个接口 SQL 太多了」

| 步骤 | 操作 |
|------|------|
| 先去哪 | **SQL 排行** |
| 怎么筛 | 按表名、语句类型（SELECT 等）、菜单名缩小；结束时间覆盖事发段 |
| 重点看什么 | **P95**、**执行次数**、**最大耗时** |
| 下钻 | 点击行 → **SQL 详情** → 「最近执行记录」「调用此 SQL 的接口」 |
| 转研发 | 带 SQL 指纹文本 + 关联接口 URL + 典型 TraceID |

也可从**接口详情 → SQL 模式聚合**跳转过来（会提示「从接口视角切到 SQL 视角」）。

---

### 场景 4：数据库层面慢（不一定对应某个 WMS 操作）

**客户怎么说**：「数据库 CPU 高」「晚上定时任务跑很久」「DBA 说慢日志很多」

| 步骤 | 操作 |
|------|------|
| 先去哪 | **慢查询** |
| 怎么筛 | 时间范围；可按表名、客户端 IP、耗时区间（≥10s 等）过滤 |
| 重点看什么 | **Top 慢查询表**（哪张表拖累最多）；**耗时 SQL 排行榜**（指纹聚合总耗时）；明细的**扫描比**（扫得多、返回少越可疑） |
| 下钻 | 点击 Top 表 → 自动填入表名筛选；点击指纹行 → 指纹详情抽屉；点击明细行 → 完整 SQL |
| 转研发 | 带指纹文本、schema/表名、典型慢查时间与扫描行数 |

> 此场景不要用 SQL 排行代替——SQL 排行只看应用内执行的 SQL，看不到定时任务或直连 DB 的语句。

---

### 场景 5：系统**现在正在卡**（实时）

**客户怎么说**：「页面转圈不动」「现在所有人都操作不了」「刚点下去没反应」

| 步骤 | 操作 |
|------|------|
| 先去哪 | **实时运行**（侧边栏有进行中数量角标） |
| 先看 KPI | **进行中**是否突然变大；**卡住数**是否 ≥ 1；**异常率**是否持续 ≥ 2% |
| 再看列表 | 「进行中的请求」按已跑时长排序；看**当前阶段**和**风险**列 |
| 下钻 | 点击行 → **实时请求详情**（可暂停自动刷新细看）；请求结束后引导去**入站请求**按 TraceID 查完整记录 |
| 转研发 | 卡住数持续 > 0 且阶段为「卡在数据库」→ 结合慢查询；「卡在外部接口」→ 查云盒；全面无响应 → 线程诊断 |

**当前阶段含义**：

| 阶段 | 含义 |
|------|------|
| 执行中 | 正常处理中 |
| 卡在数据库 | 正在等 SQL 返回且已等 ≥ 5 秒 |
| 卡在外部接口 | 正在等云盒（外部接口）返回且已等 ≥ 5 秒 |
| 无 I/O 活动 | 暂无明显 DB/外部调用，但已空闲 ≥ 60 秒 |

**风险**：正常 / 需关注 / 重点关注——优先处理「重点关注」且持续时间最长的。

**当前积压 TOP**：按 URL / 操作人 / IP 汇总正在跑的请求，快速判断「哪个接口、谁、哪台客户端」在拖慢系统。

---

### 场景 6：全面超时，怀疑锁竞争或死锁

**客户怎么说**：「所有操作都超时」「系统像冻住了」「线程是不是死了」

| 步骤 | 操作 |
|------|------|
| 先去哪 | **线程诊断** |
| 操作 | 点击「**采集快照**」（会短暂停顿 JVM，勿频繁点击） |
| 先看 | 默认「**需关注**」列表；**死锁**卡片 > 0 立即转研发 |
| 下钻 | 点击 KPI 卡片筛选 → 点击线程行 → 抽屉看**调用栈**、**锁链** |
| 转研发 | 死锁：导出 jstack 立刻转研发；锁竞争：看「影响」列数字最大的持锁者，截图锁链 |

**判断顺序**：

1. 死锁 > 0 → P0，立即处理。
2. 阻塞（锁竞争）> 0 → 看持锁者栈顶是否在等 I/O（慢 SQL 占锁常见）。
3. I/O 等待 > 0 但阻塞 = 0 → 业务超时但无锁，优先查慢 SQL / 外部接口。
4. CPU 偏高 > 0 → 看栈顶 `com.digiwin` 业务帧（大循环、排序、序列化）。

---

### 场景 7：页面加载慢、返回数据量太大

**客户怎么说**：「打开报表要很久」「接口返回几十 MB」「浏览器卡死」

| 步骤 | 操作 |
|------|------|
| 先去哪 | **大对象监控** |
| 选 Tab | 数据库大对象（SQL 返回过大）/ 云盒大对象（外部接口响应过大） |
| 重点看什么 | **严重等级**（严重 > 警告 > 关注）；返回行数、Bytes、扫描比 |
| 下钻 | 点击行 → 详情抽屉看完整 SQL 或接口地址 |
| 转研发 | 带 schema/表名或接口 URL、Bytes 大小、发生时间 |

**纳入标准**：

- 数据库：返回 ≥ 1MB **或** 返回行数 ≥ 1000。
- 云盒：响应字节 ≥ 1MB。

---

### 场景 8：客制代码问题

**客户怎么说**：「升级标准版后客制功能报错」「wms-custom 相关异常」

| 步骤 | 操作 |
|------|------|
| 先去哪 | **入站请求** 或 **接口详情**（高级筛选「是否客制」） |
| 识别标志 | URL 旁「**客**」徽章；错误信息含 `wms-custom` |
| 下钻 | 请求详情 → 错误 Tab + 响应体 |
| 转研发 | 转客制开发团队，附带 TraceID、操作描述、错误全文 |

---

### 共用：请求详情怎么读

从入站请求、接口详情、SQL 详情、实时运行均可打开**请求详情**弹窗。

**四步阅读法**：

1. **总耗时 + 瓶颈诊断** — 系统自动判断最可能原因，按优先级：
   - 有特别慢的一条 SQL → 先查这条慢 SQL
   - SQL 条数很多 → 可能重复查询过多
   - 云盒调用慢或占比高 → 瓶颈在外部接口
   - 应用侧时间占多 → 应用内部逻辑耗时
   - 数据库总时间偏多 → 数据库整体偏慢

2. **时间花在哪** — 汇总条显示 SQL / 云盒 / 应用各占多少。

3. **瀑布图** — 按时间轴排列每次 SQL、云盒调用；点击色块看单条详情（Mapper 方法、是否慢查、是否异步）。

4. **Tab 区** — 基础信息、关联 SQL、关联云盒、请求体、响应体/错误信息、请求头。

**实时请求结束后**：弹窗会提示「请求已结束，请前往入站请求用 TraceID 查看完整记录」。

## 四、通用操作技巧

| 技巧 | 说明 |
|------|------|
| 时间筛选 | 主用「结束时间」；「开始时间」在高级搜索里 |
| 趋势图下钻 | 点击有数据的柱子缩小时间范围；缩到 < 10 秒不可再缩；左右箭头平移时段 |
| 对比模式 | 接口详情 / SQL 详情可开「对比」，默认与昨天同期比；可看分栏 / 叠加 / 差异三种视图 |
| 耗时分布图 | 左绿右红表示快→慢；点红色柱子直接列出该档明细；可调整横轴上限 |
| 面包屑回退 | 顶部 ContextBar 点击上级标签返回（如从请求详情回到接口详情） |
| 分享现场 | 筛选条件写入浏览器地址栏，复制 URL 发给同事可还原同一视图 |
| 分页上限 | 单次查询最多 1 万条，时间范围过大时需缩小 |

## 附录 A：菜单功能速查

### A.1 入站请求

| 项 | 内容 |
|----|------|
| 用途 | 按时间检索每一次 API 请求，进入瀑布详情 |
| 数据源 | 应用侧（ES `wms-monitor-request`） |
| 主要筛选 | 结束/开始时间、TraceID（精确）、URL/菜单/操作描述/操作人/错误信息（模糊）、客户端 IP/业务单号（精确）、是否异常/慢 SQL/慢请求 |
| 列表指标 | URL、设备类型、菜单、操作描述、操作人、TraceID、开始/结束时间、耗时、是否异常、错误信息、慢 SQL、业务单号、SQL 数 |
| 图表 | 请求量趋势（蓝=正常，红=异常） |
| 下钻 | 点行 → 请求详情；点趋势柱子 → 缩小时间 |

### A.2 接口分析 / 接口详情

| 项 | 接口分析 | 接口详情 |
|----|----------|----------|
| 用途 | URL 维度性能排行 | 单接口趋势、耗时分布、SQL 模式 |
| 数据源 | 应用侧 | 应用侧 |
| 主要筛选 | 结束时间、接口路径、操作名称、菜单、操作人、是否异常/慢 SQL/客制 | 同左 + 对比模式 |
| 核心指标 | 请求量、错误率、平均耗时、P50/P95/P99 | 总请求数、总 SQL 次数、平均 SQL 数/请求、平均响应耗时 |
| 下钻 | 点行 → 接口详情 | 最近请求 → 请求详情；SQL 模式 → SQL 详情；耗时分布柱子 → 过滤慢请求 |

### A.3 SQL 排行 / SQL 详情

| 项 | SQL 排行 | SQL 详情 |
|----|----------|----------|
| 用途 | SQL 指纹聚合排行 | 单指纹趋势与调用方分析 |
| 数据源 | 应用侧（ES `wms-monitor-sql`） | 应用侧 |
| 主要筛选 | 结束时间、表名、语句类型、是否异常、菜单、操作名称、操作人 | 结束时间 + 对比模式 |
| 核心指标 | 执行次数、平均/最大耗时、P50/P95/P99 | 总执行次数、平均/最大耗时、关联接口数 |
| 下钻 | 点行 → SQL 详情 | 最近执行 → 请求详情；关联接口 → 接口详情 |

### A.4 慢查询

| 项 | 内容 |
|----|------|
| 用途 | 数据库慢查分析（DB 侧采集） |
| 数据源 | MariaDB 慢日志（ES `mariadb-slowlog`） |
| 主要筛选 | 时间、表名、客户端 IP、耗时区间 |
| 模块 | 请求量 & 总耗时趋势；Top 慢查询表（Top 8）；耗时 SQL 排行榜（指纹）；慢查明细 |
| 明细指标 | 时间、耗时、数据库、表、返回行、扫描行、影响行、Bytes、扫描比、SQL |
| 下钻 | Top 表 → 填表名筛选；指纹行 → 指纹抽屉；明细行 → 慢查抽屉 |

### A.5 实时运行

| 项 | 内容 |
|----|------|
| 用途 | 进行中 API 实时分析 |
| 数据源 | WMS JVM 内存（约 1 秒刷新） |
| 控制项 | 显示 Top 10/20/50；流量窗口 1/2/5 分钟；高级搜索 URL/操作人/操作描述/IP |
| KPI | 进行中、进入/完成、异常率、慢 SQL 请求、卡住数 |
| 列表指标 | URL、操作描述、当前阶段、已等待、持续时间、风险、SQL 数、云盒数、慢 SQL、操作人、TraceID |
| 下钻 | 点行 → 实时请求详情；结束后 → 入站请求（TraceID） |

### A.6 线程诊断

| 项 | 内容 |
|----|------|
| 用途 | 一次性 JVM 线程快照诊断 |
| 数据源 | WMS JVM（点击采集，非轮询） |

## 附录 B：页面问号帮助索引

### B.1 接口分析 / SQL 排行 — 百分位

| 指标 | 含义 | 怎么看 |
|------|------|--------|
| **P50** | 耗时从快到慢排序，中间那个数；一半比它快，一半比它慢 | 看「通常快不快」 |
| **P95** | 100 次里 95 次不超过此时间；排行默认按它排序 | 看「慢的那部分」；偏高优先点进去 |
| **P99** | 100 次里 99 次不超过此时间 | 看「最慢 1%」；偶发超时常把它顶高 |

### B.2 实时运行 — KPI 条

| 指标 | 含义 | 怎么看 |
|------|------|--------|
| **进行中** | 此刻未结束的请求数 | 突然变大或持续升高 → 系统可能忙不过来 |
| **进入 / 完成** | 流量窗口内新进 / 已完成数 | 进入远大于完成 → 积压加剧 |
| **异常率** | 窗口内完成请求的错误占比 | 正常接近 0%；≥ 2% 持续 → 去入站请求筛异常 |
| **慢 SQL 请求** | 窗口内完成且含慢 SQL 的请求数（非语句条数） | ≥ 1 标黄 → 去慢查询或 SQL 排行 |
| **卡住数** | 进行中且等 DB/外部 ≥ 5s，或空闲 ≥ 60s | ≥ 1 → 看下方列表「当前阶段」 |

### B.3 线程诊断 — KPI 与严重度

| 卡片/等级 | 含义 | 怎么用 |
|-----------|------|--------|
| **需关注** | 死锁、锁竞争、CPU 偏高、I/O 等待、持锁且有人等 | 客服默认先看这里 |
| **死锁** | JVM 检测到线程互持锁成环 | > 0 立刻导出 jstack 转研发 |
| **阻塞** | 抢 synchronized 锁未进入（BLOCKED） | 看「影响」列，数字大的持锁者优先 |
| **CPU 偏高** | 100ms 窗口 CPU ≥ 40% | 看栈顶 `com.digiwin` 业务帧 |
| **I/O 等待** | RUNNABLE 但在等 socket/DB，CPU 低 | 业务超时但阻塞=0 时优先看 |
| **P0** | 死锁或锁竞争 | 必须优先处理 |
| **P1** | I/O 等待、业务等待、CPU 偏高 | 查慢 SQL / 外部接口 / 下游任务 |
| **P2** | 空闲等待或正常运行 | 通常不是故障点 |

### B.4 大对象 — 严重等级

**数据库 Tab**

| 等级 | 条件 |
|------|------|
| 关注 | bytes ≥ 1MB 或 rows ≥ 1000 |
| 警告 | bytes > 10MB 或 rows > 5000 |
| 严重 | bytes > 100MB 或 rows > 10000 |

**云盒 Tab**（仅按字节）

| 等级 | 条件 |
|------|------|
| 关注 | ≥ 1MB 且 ≤ 10MB |
| 警告 | > 10MB 且 ≤ 100MB |
| 严重 | > 100MB |

### B.5 耗时分布图

| 要点 | 说明 |
|------|------|
| 看什么 | 每次请求/执行按耗时分组：左绿（快）→ 右红（慢） |
| 紫色线 | 累积完成比例；圆点标 P50/P95/P99 位置 |
| 操作 | 点红色柱子列出该档明细；可开对比看是否比平时更慢 |

### B.6 对比模式

| 模式 | 说明 |
|------|------|
| 分栏 | 本期与对照期上下各一张图，适合细看 |
| 叠加 | 灰=对照期、彩=现在，适合快速扫变化 |
| 差异 | 只显示增减；红=变差、绿=变好 |

### B.7 请求详情 — 瓶颈诊断优先级

1. 单条特别慢的 SQL
2. SQL 条数过多（重复查询）
3. 云盒（外部接口）慢或占比高
4. 应用内部耗时
5. 数据库总耗时偏多
